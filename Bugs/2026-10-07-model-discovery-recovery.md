# 启动后型号未确认，RC003 三键增强区域偶发消失

- 发现日期：2026-10-07。
- 状态：修复已实现，自动化验证通过；型号失败后的 Windows 真机恢复待验收。
- 影响范围：无线麦 SayAll Windows 版 0.2.8。RC003 用户可能遇到增强区域消失；RC001/RC003 共用的型号发现链均可能返回未知。
- 责任层：Windows BLE 型号发现，以及前端三键增强区域的显示条件。
- 症状：用户报告有时启动后完全看不到三键增强区域及开关，重启应用后恢复；偶发、尚无稳定复现步骤。
- 预期行为：型号暂未确认时仍显示功能及不可用原因；应用在不阻塞语音的条件下补充识别。只有明确识别为 RC003 才允许启动 Helper。

## 已确认的代码链与归因边界

检查基线为提交 10474eb5d1bc8af7f9d5f64352baac70cde2c6f0：

1. is_supported_remote_name 接受 MI RC 等通用名称，但 remote_model_from_name 不把它们推断为 RC003。
2. BleSession::connect 在名称不能确定型号时，同步读取一次标准 Device Information / Model Number（2A24）。
3. 服务发现、特征发现、读取或解析失败均返回 None，没有对应步骤、GATT 状态或 HRESULT 日志；随后型号设为 Unknown，共用 ATVV 建链仍可继续。
4. 该连接内没有后续型号补识别。Raw Input 的设备到达处理只更新自身监听状态和设备族匹配，不更新 BLE 型号。
5. Rc003InputControl.vue 原来仅在 remoteModel === "rc003" 时渲染，所以 Unknown 会隐藏整个区域。Helper 状态读取失败或未连接只影响按钮状态和文案，不会单独隐藏区域。

这条代码路径已经确认，但不能据此断定用户每次偶发故障的具体系统触发原因。本次保留的正式应用现场为 Ready / RC003，未捕获型号读取失败或 Unknown 的现场。设备名已能明确识别 RC003 时不会走旧的 2A24 回退路径；首次运行快照迟到也能使页面暂时显示未知，需要现场证据区分。

目前没有证据证明此现象与 RC003 Helper IPC 高 CPU 同源。型号来自 BLE 连接快照；Helper 状态不会改写该字段。

## 修复

- 建链时保留原有精确名称识别，不把 MI RC 等泛名称视为 RC003。移除建链线程上的同步 2A24 读取。
- 首次补识别由 ATVV 就绪触发，仅在连接 Ready、语音 Idle 且尚未请求打开麦克风时派发到独立线程。
- 失败重试复用既有连接退避的 2 秒、4 秒间隔，每个连接最多计入三次实际失败。请求编号与失败计数分离；正常语音抢占不消耗失败预算，取消后仍需等待既有基础退避及空闲条件。
- 同时只允许一个型号读取任务。连接改变时取消旧任务，新连接也须等旧任务的异步结果及资源清理完成后才能启动新读取。
- 每次读取使用既有 REQUEST_TIMEOUT 作为整个尝试的有界等待预算，通过 WinRT 完成回调和条件变量唤醒，不轮询操作状态，不阻塞 BLE 语音线程。
- 开始语音、断连及退出清理均请求取消在途操作。结果按独立的 connection_generation 隔离，不使用随语音会话改变的 snapshot.generation。
- 只关闭探测线程取得的 Device Information 服务；不关闭共用 BluetoothLEDevice，不触碰 ATVV 已有服务。迟到或服务数量异常的结果也由 RAII 关闭。
- 未知型号时保留三键增强区域，显示“型号尚未确认”及暂不可用说明，禁用开关且不轮询或启动 Helper。确认 RC003 后自动恢复原操作；确认 RC001 后隐藏仅适用于 RC003 的增强区域。
- 增加脱敏日志，覆盖推断、读取步骤、状态、HRESULT、重试、失败预算耗尽和迟到结果；不记录设备名原文、型号特征原文、地址或设备标识。

## 已知边界

WinRT 取消是一个请求。若操作在取消或超时后一直不回调，当前单飞槽保持占用，避免叠加新 GATT 请求和工作线程；语音及现有 ATVV 连接仍可继续。此时型号仍未确认，界面保留不可用说明，不承诺无限自动重试。需要结合 remote_model 日志识别取消后未结算的操作；不通过关闭共享设备对象强行释放该槽。

当前单元测试验证了取消/超时返回与迟到结果清理逻辑，但真实 OS 永不回调以及语音抢占时的取消及时性未作硬件实测。

## 下一次现场取证

在重启前保留同一 PID 的连接型号、连接阶段及增强区域状态，提取相同连接纪元的 remote_model、runtime_snapshot 和 ble_connect 日志：

- Ready/Streaming + Unknown：检查型号发现步骤、GATT status、HRESULT、失败次数及是否耗尽。
- 型号已为 RC003，但页面仍显示未知：检查运行快照是否未返回或未更新。
- 出现 voice_preempted：应等待语音结束及退避后继续，不增加实际失败计数。
- 出现 timeout 或 connection_cancelled：结合后续重试/应用结果判断操作是否已结算，区分系统未回调与正常取消。
