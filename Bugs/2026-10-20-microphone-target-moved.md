# 普通麦克风挤占遥控器目标区

- 发现日期：2026-10-20。
- 状态：已修复；本机完整安装与原始操作回验 passed。
- 影响范围：0.3.12 本地测试包的麦克风选择界面，不涉及按键或语音协议。
- 功能点：遥控器目标偏好、当前系统默认录音设备与界面分组。
- 现象：点击普通麦后，普通麦出现在目标区，CABLE Output 被移入其余列表；绿色高亮不符合用户要求。
- 复现条件：旧版本选择普通麦。用户截图及本机原生辅助功能树均确认了物理目标、CABLE 位于其余列表，且遥控器尚未就绪。
- 正常预期：CABLE 保持在遥控器目标区；普通麦留在下方并能立即使用；实际默认录音端点以克制高亮及按钮文案表达。
- 根因：所有选择按钮共用 `select_microphone`。离线点击也会把普通麦写入 `target_microphone_id`；界面再依据该字段移动行。这不是设备枚举丢失或驱动异常。
- 修复：固定按虚拟／普通 Capture 分组；普通麦独立手选，保留虚拟目标并在成功后结束恢复所有权；旧物理目标仅迁移到唯一可验证的虚拟线路。去掉绿色选中底色，保留一次性轻微动效。
- 验证：55 项组件、35 项宿主、27 项平台、四组浏览器检查及真实接口往返 passed；安装版实际切换两只普通麦、重新应用 CABLE 后目标仍在上方，三个 Capture 回原麦、三个 Render 不变。启动仅迁移目标两个字段。详见 [WindowsDefaultMicrophone](../Testing/WindowsDefaultMicrophone.md)。实体遥控器连接／断连及听写仍 deferred，不以界面或 API 测试替代。
- 隐私检查：本记录不含个人路径、设备身份、语音内容或凭据；详细证据仅存本地忽略目录。
