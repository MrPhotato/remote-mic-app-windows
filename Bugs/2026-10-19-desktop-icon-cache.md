# 升级后桌面仍显示旧图标

- 发现日期：2026-10-19。
- 状态：等待安装后可见效果验证。
- 影响范围：本机 Windows，0.3.6/0.3.7 升级；与遥控器型号无关。
- 功能点：安装器、桌面快捷方式图标。
- 现象：应用内为新版银灰遥控器图标，用户确认桌面仍是旧图，0.3.7 定向通知后仍未改变。
- 复现条件：保留既有桌面快捷方式升级，观察桌面显示；是否在其他电脑复现未知。
- 正常预期：升级后已有默认快捷方式使用随应用提供的新图标；不改变其他快捷方式或用户自定义图标。

## 证据与归因边界

- 已安装 exe 的 16/24/32/48/64/128/256 七帧与仓库 ICO 一致，应用内 PNG 也一致。
- 在普通用户环境读取用户和公共桌面，只发现一个相关链接，目标正确，IconLocation 为默认值；开始菜单链接也正确。两个 OneDrive 根下均无桌面目录。
- 公开 Shell API 返回该桌面链接的 32/48/256px 都为新版，48/256px 与源 ICO 提取图逐字节一致。向用户展示后，用户确认实际桌面与该图不同。
- 0.3.7 安装后的 SHChangeNotify 定向通知不能解决本次可见现象（failed）。可确认资源和链接目标正确、现有 Explorer 显示与新进程读回不一致；不能据此证明某个具体内部缓存文件损坏。没有清缓存或重启 Explorer 来制造验证结果。

## 修复与验证

- 同一源 ICO 通过 Tauri resources 映射为 `sayall-shortcut-532a10a81c7d.ico`，使用新资源位置避开旧 exe 图标关联。没有重复维护第二份源图。
- NSIS 加载原链接，仅对目标匹配且仍为默认图标/index 0 的链接执行 SetIconLocation、Save 和路径级通知。保留启动目标、参数、工作目录、热键、描述、窗口模式；明确自定义图标和错误目标不改。资源不存在、读取或保存失败有具体阶段日志。
- 生产宏独立编译 passed；`scripts/test-installer-icon-notification.ps1` 24 项范围检查 passed。
- `scripts/test-installer-shortcut-icon.ps1` 创建独立临时链接，不执行假目标文件。8 场景×3 轮 passed：默认/显式 exe 默认图标迁移、错误目标、自定义图标、非零索引、已有独立图标、损坏/缺失链接、缺资源；六项属性、七个寄存器和栈保持，重复调用不重写链接。
- 本机实际安装、既有快捷方式属性核对及桌面可见回验待完成（deferred）。新进程图标读取或 API 成功不替代用户的桌面观察。
- 交互式全新安装在完成页才首次创建桌面链接，使用 exe 新图标；本修复覆盖已有链接升级、静默/被动安装。以后更换 ICO 必须显式迁移已知旧产品图标，不能泛化覆盖任意同前缀自定义图标。
