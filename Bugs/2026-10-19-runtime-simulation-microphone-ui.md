# CI 麦克风仿真未同步新版选择流程

- 发现日期：2026-10-19。
- 状态：修复已完成本地回归，等待云端 WebView/IPC 验证。
- 影响范围：PR #12 的 Windows CI；不据此判断真实遥控器或麦克风发生故障。
- 功能点：Windows runtime-simulation、连接与语音页面。
- 现象：运行 `39229236930` 在 `Test Windows Tauri WebView and IPC runtime simulation` 失败，报告「等待 真实录音端点名称 超时」。
- 复现条件：在 `ce098843c5871f4fc2c9f5326b8ada58bd2ebf96` 执行完整 Windows CI。
- 正常预期：经过当前麦克风页面与真实 Tauri IPC，验证目标 Capture、普通麦克风选择、内部 Render 配对和恢复状态。
- 根因：前端仿真仍读取已移除的 `.setting-row span`，并依赖「高级设置」「更换麦克风」旧入口；新增默认麦克风控制器在仿真模式使用 unavailable 后端，无法产生就绪目标。此前本地完整预检仅编译原生仿真程序，没有执行其界面旅程。
- 修复：更新共享麦克风界面旅程，加入普通麦克风与 CABLE 往返选择及 IPC 读回；为显式 `runtime-simulation` feature 增加内存录音设备 API，复用正常宿主的校验、启动选择、设置保存和退出恢复流程，不调用真实音频 API。生产初始化逻辑不变。
- 预防：组件回归直接执行同一界面旅程，普通本地预检即可发现旧选择器；CI 加入三项仿真生命周期测试，失败时保存步骤报告及进程输出。外观断言限定外观卡片，避免软件更新网络错误被误判为外观失败。
- 验证：前端 297 项、类型检查、Rust 格式检查及三项后端仿真生命周期测试 passed；其中共享界面旅程检查正常往返、后台状态不一致时必须失败。云端完整运行结果单独核验，不以组件测试替代真实 WebView/IPC。
- 边界：本次不安装或启动本机应用，不改用户配置、系统录音/播放默认值或蓝牙。实际自动升级与重启仍见 `Testing/WindowsOneClickUpdate.md` 的待验收项。
- 隐私检查：仅使用仿真设备身份和公开提交/运行编号，无个人路径、语音内容或凭据。
