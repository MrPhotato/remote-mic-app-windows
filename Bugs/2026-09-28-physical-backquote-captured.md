# 连接遥控器后，普通键盘反引号被识别为 TV

- 发现日期：2026-09-28。
- 状态：修复中，等待本次 Windows 实体复验。
- 影响范围：0.2.7 Preview；已连接并配置 Home/TV 映射时的普通键盘。
- 现象：反引号及 Shift＋反引号触发其它功能；用户另报一次持续重复反引号。
- 复现条件：遥控器在线、TV 配有映射，使用普通键盘反引号。卡住事件的现场日志与精确时序未知。
- 正常预期：普通键盘保持原生输入，仅来自指定遥控器的事件触发映射。

## 证据与根因

旧 `button_mapping::persistent_suppress_mask` 把 Home/TV 放入常驻拦截掩码；
`key_gate::handle_keyboard` 只凭虚拟键和连接状态，把物理键盘的 OEM_3 当作遥控器 TV。
Shift 不改变 OEM_3 的归因，故波浪号同样被接管。移除常驻掩码本身不足够：
遥控器活动后的四秒武装以及吞键后的自我续期仍可能误吞相同虚拟键。

按住期间启动钩子、监听或映射状态切换时，旧路径也可能只记录重复 DOWN，
却未记录已进入系统的首次 DOWN；后续 UP 被吞后有粘键风险。
这是代码层面可复现的配对缺口，不能断言就是用户那次连续反引号的唯一原因。
现有现场日志记录了 TV 映射触发，但没有物理设备来源，不能用来证明该次卡键已复现。

## 修复边界

Home/TV 只在已完成设备匹配的 Raw Input 中解码，不参与无设备身份的全局吞键或武装。
因此普通键盘的按下、重复和松开均透传，包括启动/停用期间的跨边沿操作。
显式打开的快捷键录入框仍按录入功能正常收集按键。
没有更改语音 F5、听写时序或其它遥控器键的策略。

代价：遥控器自身的 Home/反引号原生事件也可能进入前台，与映射动作同时发生；
按住时可能重复原生输入。当前公共低级键盘钩子不提供设备身份，不能保证
既拦下某个设备的同键事件，又无损放行其它键盘。界面与 README 明示此边界。
