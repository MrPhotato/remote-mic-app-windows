# 方向键长按前原生方向键泄漏

- 发现日期：2026-10-21。
- 状态：根因已确认；修复待方向键报告处理的明确授权与本地验证。
- 影响范围：本机 RC003，安装版 0.3.19，程序来源提交 `648f22b944638cd4bae1e7691c11a2e8aec83f22`。RC001 本轮未测。
- 功能点：方向键长按、原生按键抑制、选定设备来源归因。
- 现象：上键长按已配置快捷键，但会先执行原生 ↑。
- 配置：映射开启，Up Single=Up、Double=Disabled、Long=LeftControl+LeftAlt+L。
- 正常预期：完成长按只执行一次长按动作，不提前发出普通 ↑；普通键盘方向键保持正常。

## 现场证据

读取当前安装版结构化日志、保存配置与源码，没有重启进程、修改配置或连接。
下表时间均为 UTC，`lk` 为累计原生 DOWN 泄漏计数。

| Up DOWN | Up UP | 持续 ms | Long 距 DOWN ms | lk 前 → 后 | 应用 Single |
| --- | --- | ---: | ---: | --- | ---: |
| 06:25:06.757 | 06:25:09.083 | 2326 | 552 | 72 → 73 | 0 |
| 06:25:42.263 | 06:25:44.003 | 1740 | 557 | 73 → 74 | 0 |
| 06:25:48.069 | 06:25:49.792 | 1723 | 559 | 74 → 75 | 0 |

三轮均记录一次 `map_fire button=Up trigger=Long`，没有 Up Single。
对应的 `map_inject result=submitted target_result=unknown` 只证明提交注入，不能证明目标应用执行快捷键。
泄漏计数在三次 Up 首沿各增加一次，随后保持不变；与用户观察到原生 ↑ 一致。
脱敏基线与筛选日志保留在忽略目录 `target/local-launch/direction-hold-20261021/`。

## 根因与覆盖范围

`button_gestures.rs` 在配置 Long 时不在 DOWN 执行 Single；550ms 到期只执行 Long，
长按后的 UP 不补发 Single。该逻辑本轮工作正常。

方向键仍通过 `key_gate.rs` 的低级键盘钩子与 Raw Input 归因：最多等待 60ms，
选定来源归因后仅武装该键 4 秒。此前真实实验已经确认 RC003 的 keyboard-only
Raw Input 可能在钩子放行后才能到达，因此隔离首按无法及时抑制。
本轮三次同键按压间隔均超过 4 秒，与该路径一致。
`native_pending` 只能防止同键 Single 重复注入，无法撤回已交给 Windows 的原生事件。

源码交叉检查结论：

| 按键 | 原生首沿保护 |
| --- | --- |
| 上、下、左、右 | 仍用旧归因路径，闲置首按可能泄漏；不属于当前 Helper 清除范围 |
| 确认、TV | 所选 RC003 的增强报告处理就绪后有专门保护；未就绪或停用时不保证 |
| 主页 | 不做无来源的全局抑制，没有同等首沿保护 |
| 菜单、电源 | 可识别的专用键码路径可直接归因；不等于所有报告形式都受保护 |
| 返回、音量±、静音 | 取决于专用键码、标准媒体键或别名报告路径，不存在统一报告清除保证 |
| 语音 | 独立按下/释放生命周期，不属于单击、双击、长按手势 |

参考此前持锁实测：[方向键归因死锁调查](../docs/investigations/2026-09-06-left-double-response-arm-deadlock.md)。
微软公开 [KBDLLHOOKSTRUCT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-kbdllhookstruct)
不包含设备句柄；[RIDEV_NOLEGACY](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawinputdevice)
仅阻止注册应用自己的旧式消息，不能据此保证拦截其他前台应用的原生方向键。

## 最小修复方案与授权边界

当前 AGENTS.md 与 [ADR 0003](../docs/decisions/0003-rc003-optional-input-helper.md)
只授权 TV 与确认键的有限报告修改，未授权方向键。以下为待授权方案，没有实施：

- 仅在所选 RC003、增强已显式开启且该方向配置了 Long/Double 时接管对应方向报告槽位；普通单击默认路径保留。
- 限定四方向 HID usage：Right=0x004F、Left=0x0050、Down=0x0051、Up=0x0052。
- 复用已验证来源、同代真实中性状态、读取/清除验证与失败还原；只以增强来源送入该方向手势，避免双来源重复。
- 配置或来源代次改变、增强失效时取消未完成手势，不补发映射单击；任何泄漏 DOWN 的 UP 必须放行。
- 不扩大第三方应用、其它报告、驱动或蓝牙操作；不延长全局等待或武装时间，不用反向方向键补偿。
- 先构建本地测试包。验证短按、长按、双击、闲置后首次使用、普通键盘负对照及按住时停止/退出边界。
