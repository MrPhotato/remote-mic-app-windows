# TV 映射生效时仍输入原生字符：与普通键盘的来源区分

- 发现日期：2026-10-07。
- 状态：调查中；TV 原生字符尚未消除，待设备层方案。
- 影响范围：Windows 上运行的个人 fork v0.2.8（`10474eb5`）、RC003 遥控器；具体 Windows 构建号未随本次采样记录。RC001 未验收。
- 功能点：TV 映射、普通键盘 OEM_3 输入隔离。
- 现象：用户报告 TV 映射动作有效，但前台同时输入 `·`。
- 复现条件：遥控器在线、TV 已配置映射，在可编辑文本框按 TV。
- 正常预期：TV 仅执行配置动作，普通键盘反引号及其 Shift 组合仍保持原生输入。

## 真机采样

保留正在运行的故障实例，另开独立被动观察器。用户依次按普通键盘反引号
3 次、Shift＋反引号 3 次、遥控器 TV 3 次，反馈文本框结果为
`···~~~···`。字符结果来自用户实体操作反馈；观察器没有采集文本框内容。

观察器仅保留 `VK_OEM_3`（`0xC0`）与 `VK_HOME`（`0x24`）的原始键值、
扫描码、标志、消息类型和相对时间。Raw Input 内部按 VID/PID 判断来源，
只落盘 `remote`／`other` 分类；低级键盘钩子不提供设备身份，不为其填写来源。
钩子始终透传，不吞键、不注入，回调只写内存。

证据：

- [Raw Input 采样](../Testing/evidence/tv-source-raw-20261007.csv)
- [低级键盘钩子采样](../Testing/evidence/tv-source-hook-20261007.csv)
- [观察器完成与清理状态](../Testing/evidence/tv-source-observer-20261007.txt)

60 秒观察窗口中，两个通道各收到 18 条目标边沿，对应 9 次完整按下／释放。
没有 Home 事件。依据用户的操作顺序和 Raw Input 来源，分组如下：

| 实体操作 | Raw Input 相对时间范围（秒） | Raw Input 来源 | 次数 |
| --- | --- | --- | --- |
| 普通键盘反引号 | 23.870–25.023 | `other` | 3 |
| 普通键盘 Shift＋反引号 | 26.837–28.004 | `other` | 3 |
| 遥控器 TV | 30.194–33.058 | `remote` | 3 |

Shift 本身不在观察器的记录范围内；该分组的组合键含义由用户执行的测试序列确认。

## 已确认事实与边界

三组操作在低级键盘钩子中完全同形：`vk=0xC0`、`make=0x29`，按下为
`flags=0x00, message=0x0100`，释放为 `flags=0x80, message=0x0101`。
因此本次样本不支持通过 VK、扫描码或这些标志区分 TV 与普通键盘反引号。
不能将按压长短或两个通道的到达先后当成可靠设备归因。

Raw Input 的三组键值、扫描码也相同，释放标志为 `0x01`；它的设备来源可
将最后三次遥控器事件与前六次普通键盘事件区分。不同通道的 flags 定义不同，
不能把 Raw Input 的 `0x01` 与钩子的 `0x80` 当作设备差异。

当前 `raw_input::button_for_keyboard` 不在无设备身份的解码路径中识别
Home/OEM_3；`key_gate` 也不为 Home/TV 武装全局抑制。已归因的 Raw Input
仍可触发 TV 映射。这个策略保留普通键盘输入，同时允许遥控器同名原生事件
进入前台，与本次 TV 输入字符的现象一致。背景见
[普通键盘反引号隔离修复](2026-09-28-physical-backquote-captured.md)。

本次只确认目标键事件的来源与形态，不确定前台输入法／布局将 OEM_3 显示为
`·` 的具体配置，也不证明语音键失效与 TV 原生字符存在因果关系。

## 修复状态

### 2026-10-08 用户补充：此前同场景正常，昨日新出现

多余字符；故障在昨日出现，出现前没有修改代码。用户自行重启应用、重新连接
蓝牙后，现象仍在。此项是用户现场反馈，不应改写为“原生字符一直存在”。

本次源码与历史核查确认：当前分支的 Home/TV 隔离逻辑最后修改于 2026-09-28
提交 `2b3ad8b`；从已发布来源 `10474eb` 到当前 `19c4772`，`key_gate`、
`raw_input`、`raw_input_windows`、`key_suppressor` 和 `button_mapping` 没有差异。
正常映射路径对 OEM_3 的放行早于连接、映射和武装状态判定；现有三键 Helper
不改写 TV 报告。因此，当前源码可解释字符的交付路径，**不能单独解释此次从
正常到异常的发生时间和触发原因**。不能据此认定增强状态切换、蓝牙重连、
输入法变化或某次代码更新就是根因，也不能据此认定必须新增驱动才能修复。

现场只读核查：当前安装程序版本为 0.2.10，主程序和 Helper 都在运行；当前可见
的三个配置文件与当天升级前备份一致。已知两个默认日志位置仍只见 9 月 21 日
的旧日志，尚未确认是否为本次进程的实际日志输出；不能用这些文件还原昨日状态。
后台窗口快照只见最小化窗口外壳，尚未取得本次运行的诊断摘要。没有恢复前台、
重启进程、修改配置或操作蓝牙。

- `passed`：用户确认同一输入框此前无额外字符，故障后重启、重连仍存在。
