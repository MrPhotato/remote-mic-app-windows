# ADR 0003：可选 RC003 三键输入 Helper

## 2026-10-21：普通按键长按、双击保护

用户要求检查全部长按防漏行为，并在明确“全部可配置普通按键纳入检查和验收、
按实际缺口补齐、保留普通键盘”的方案后答复“可以，去干吧”。授权范围仅为
现有可选增强中所选 RC003 的普通按键报告，本地验证；不扩展语音、其它设备、
第三方应用、驱动、服务或系统蓝牙。此节在普通按键范围内扩展之前 TV/确认键的限制。

- 协议 4 保留 `tv_enabled`、`ok_enabled`，新增必填整数 `gesture_mask`。
  旧协议拒绝接入；不猜测缺失字段，不截断高位。
- 位序固定为 Back、VolumeUp、VolumeDown、TV、OK、Up、Down、Left、Right、Home、Menu、Power、Mute；
  TV/OK 继续单独授权位，新增掩码只能是 `0x1fe7` 的子集。
- 新增报告清除只对实际配置双击或有效长按的普通键启用；普通 Backspace
  的按住连续删除不算独立长按，原有单击即时路径不整体改变。
- 所有报告处理沿用每帧来源绑定、同代真实中性状态、清除读回、调用结果与原字节恢复。
  只处理已知普通键 usage，语音 F5 与未知槽位不修改。
- 已接管键的来源只由确认过的 Helper 状态驱动；原生回声不创建第二次手势。
  未接管的返回/音量±继续只观察；新协议包含这些状态不意味着报告已清除。
- 被接管键停止无设备来源的预测式全局武装，普通键盘保持原生输入；此前吞下的 DOWN
  只清理其配对 UP，已泄漏 DOWN 的 UP 必须放行。启用前旧按住、来源交接和失效排空逐键处理。
- 配置变化、来源代次变化、失联及退出取消未完成手势，合成释放只更新显示，不补发 Single。
  增强停用后原生行为恢复；按住时停用不能保证 Windows 不再收到后续原始报告。
- 先本地构建安装，验收原始上键长按、短按、双击、普通键盘及真实闲置后首用；
  模拟时钟覆盖不视作实体闲置通过，RC001 与本机未具备的按键分别保留边界。

证据与验收见 [方向键长按](../../Bugs/2026-10-21-direction-hold-native-arrow.md)。

## 2026-10-20：确认键报告处理的有限扩展

用户明确答复“允许，仅扩展确认键并本地验证”。新增对象仅为已选 RC003
的确认键 usage `0x0028`，用于防止普通 Enter 在长按 Ctrl+Enter 之前先送入应用。
TV 和原三键的既有范围不扩大。

- 协议升级为 3；租约新增 `ok_enabled`，确认键使用 mask 位 4（值 16）。
  旧版本双方拒绝连接，不猜测缺失字段。
- 只在映射已开启、确认键有动作且本代已确认真实中性状态后接管。
  每份报告仍核对所选设备来源，仅清除本帧已授权的 TV/确认键槽位。
  清除读回、调用成功及原缓冲区恢复规则与 TV 相同。
- 确认键的按下/释放使用既有手势识别和用户映射；短按 Enter、长按
  Ctrl+Enter 的区分阈值不变，不修改语音生命周期。
- 增强有效期间，确认键语义只由确认过的 Helper 状态驱动；
  普通键盘 Enter 保留原生输入，不沿用遥控器活动武装去误吞实体键盘。
- 中途启用、按住停用、配置变化、代次变化和失效分别处理；
  取消未完成手势，不把合成松开当作单击。泄漏到 Windows 的 DOWN
  仍须配对放行 UP，不能造成粘键。
- 只构建本地包并实测冷首按、闲置首按、短按、普通键盘及按住停用。
  无授权扩展到其它报告、驱动、服务、第三方应用或系统蓝牙操作。

故障与逐项验收见 [确认键长按](../../Bugs/2026-10-20-confirm-hold-native-enter.md)。

## 2026-10-08：TV 报告处理的有限扩展

用户明确答复“允许，仅扩展 TV 并做本地验证”。原三键只读范围保持，
新增的唯一报告写入对象是**所选 RC003 的 TV usage `0x0035`**。
这是对下文原始只读决定的有限扩展，不是新的通用输入权限。

- 保留每次调用的 ContainerId / 来源绑定；共享宿主中其它设备的报告不读写。
- 只有当前 TV 已配置动作、会话有效且已经观察真实中性状态，才能在 Windows
  复制 Report 1 前清除 TV 槽位。读回确认和调用返回成功后才上报 TV 状态。
- Helper 协议升级为 2，租约包含 `tv_enabled`，TV 使用 mask 位 3。
  不匹配的旧 Helper 拒绝接入；配置、来源或代次变化先取消旧手势。
- 普通键盘的 OEM3/Home 继续全局放行；增强失效不恢复全局吞键，
  不追加 Backspace 来补偿泄漏字符。失效后取消尚未完成的 TV 手势。
- 原有返回/音量±继续只观察；不扩展到语音、Home、其它报告、驱动、服务、
  计划任务或 WUDFHost 重启，更不得操作整机蓝牙。
- 先构建本地测试包；字节级模拟、Windows 安装和实体 RC003 验收分别记录。
  冷态首按、普通键盘反引号/波浪号和按住退出等项目未完成前不宣称修复通过。

参考来源、上游方案的隔离与失败处理风险见 `ATTRIBUTION.md`；
故障证据见 `Bugs/2026-10-07-tv-native-character-source.md`。

## 原始决定（2026-09-20）

2026-09-20。用户在独立真机实验通过后明确要求接入软件。

## 依据与范围

RC003 返回、音量加、音量减在本机普通 Raw Input / GameInput 路径不可见，
但 Frida 17.18.0 观察 WUDFHost 内部 Report 1 已得到三键各 3 对真实 DOWN/UP。
详见 `Testing/WindowsRc003Frida.md`；参考固定来源和许可记于 `ATTRIBUTION.md`。
本仓库与所改编上游均为 GPLv3；本地测试包包含对应源码、构建配置和第三方许可。

这是用户明确授权的非公开 Windows 实现读取例外，只限 RC003 三键。
普通按键、基础语音、F5 生命周期仍使用原有路径，不依赖 Helper。
不安装输入驱动，不改变 Secure Boot/测试签名设置，不吞写报告。

## 决策

- 主程序普通权限，用户显式启用“RC003 三键增强”后申请一次 Windows 管理员授权。
  每次主程序启动重新选择是否启用；不注册服务、启动项、计划任务或静默提权入口。
- Helper 打包 Python/固定 Frida/固定脚本，不要求用户安装 Python。
  主程序内嵌构建清单，系统 PowerShell 执行内嵌启动逻辑，验证清单散列，
  将固定载荷复制到 Program Files 下仅管理员/SYSTEM可写的独立目录，复核完整文件散列后运行。
  不从普通用户可写目录提升加载动态 Python/JS/DLL，不提供任意脚本、PID、文件路径命令。
- 主程序预建仅 loopback 的随机端口和随机会话令牌，限制每帧 4096 字节。
  Helper 检查监听端口归属父进程，持有父进程句柄；双方心跳与 EOF 判断清理。
  协议仅有租约/选择、停止、三键绝对状态、状态与匿名错误码；不记录令牌、设备标识或路径。
- Helper 从已选择 BLE AEP ID 的公开设备关联找到 ContainerId，核对唯一 RC003 HID 实例。
  每份报告读取前验证活动调用帧及 ContainerId；共享宿主不能退回进程级归因。
  宿主、成员集合、连接或选择变化先卸载再重新绑定，保持拒绝歧义与失败闭锁。
- 三键以独立来源并入现有语义状态机，不覆盖原 HID/keyboard 状态，不触发全局归因门控。
  仅 mask 位 0/1/2 对应返回/音量±；状态按 generation/sequence 去重并拒绝迟到旧代。
  真实按下/释放复用现有高亮、单击/双击/长按/连发逻辑，不修改已有用户映射。
  未配置动作的增强按键只高亮，不擅自为 Disabled 添加系统音量行为。
- Helper 退出、丢失或新代开始时，由主程序取消三键手势计时再清除该来源、发出高亮 UP，
  不把异常释放变成单击，也不清掉其它普通键。全局监听停止、设备移除、终端动作另增输入 epoch。
- 每次 attach 必须先观察真实三键中性报告，再接受 DOWN；启动时已有按住不能当作新击。
  初次启用或重新绑定时 UI 提示按一下方向键并松开完成初始化。
  就绪之后不因普通闲置重新武装，闲置首用必须单独真机验证。

## 验证和交付边界

优先本地完整测试包，安装/升级/启动和实体功能验证后提交；不自动上传或发布。
独立探针通过不是本产品通过；RC001、异常恢复、共享宿主其它设备负对照和语音回归
须按实际证据分别报告，未执行项目标为 deferred。

非公开 UMDF ABI 可能随 Windows 更新变化；验证不通过时只停三键增强并报告匿名原因。
此模式不能宣称为普通权限公开 API 输入路径，也不保证消除后来出现的原生系统音量行为。
