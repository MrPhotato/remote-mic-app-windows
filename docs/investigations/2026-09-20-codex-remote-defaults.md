# Codex 遥控日常默认方案调研（2026-09-20）

已使用 OpenAI Docs 技能，并于 2026-09-20 实际打开核对 [OpenAI 官方 Windows 命令参考](https://learn.chatgpt.com/docs/reference/commands)。旧 `developers.openai.com/codex/app/commands` 当前也重定向至该页。本文组合键来自 Windows 表，实际用户自定义快捷键仍以应用可见设置为准。

官方 [Codex Micro 操作设计](https://learn.chatgpt.com/docs/features/codex-micro)将查看/切换聊天、审批、语音和发送安排为不同操作。本方案借鉴其职责分离：语音只录入，发送仍需用户明确按确认；不复制其设备协议、灯光状态或麦克风双击规则。以下人体操作取舍是结合本仓库状态机提出的设计判断，尚无用户对比实验支持。

## 必须说清的聊天与 Agent 边界

官方将 `Ctrl+PageUp`、`Ctrl+Shift+Tab` 和 `Ctrl+Shift+[` 列为“上一项”的替代组合；`Ctrl+PageDown`、`Ctrl+Tab` 和 `Ctrl+Shift+]` 列为“下一项”的替代组合。两类的范围均包含**聊天或标签页**。因此换用旧 `Ctrl+Tab` 组合不能据官方证据实现“只切 Agent”。[官方命令表](https://learn.chatgpt.com/docs/reference/commands)

`Ctrl+Alt+A` 针对下一个需要处理的 Codex 聊天；`Ctrl+Alt+1…6` 指向最近聊天槽位，`Ctrl+1…9` 指向编号聊天。它们并非与当前聊天相邻的上一项/下一项；最近槽位还会随应用排序变化。本轮未找到只按聊天顺序遍历、排除文件/浏览器/审查标签页的公开默认快捷键，不能据此断言应用绝无可配置命令。[官方命令表](https://learn.chatgpt.com/docs/reference/commands)

此处“Agent”应指用户侧可见的独立 Codex 任务/聊天。它不等于同一任务内部的子代理，也不等于当前工作区的文件标签页；快捷键没有提供逐个选中内部子代理的承诺。

用户于本轮确认接受 `Ctrl+PageUp/PageDown`，并自行先关闭侧边栏再切换；TV 曾设为单击开关侧边栏，最终改为双击开关侧边栏、单击查看改动。因此下表采用官方聊天/标签页切换，标签应明确写“上一个/下一个会话或标签页”。关闭侧边栏是用户选定的操作流程，不是官方保证“只切 Agent”的条件，本报告不作此推断。

若后续需要严格只切聊天任务，需先在用户可见快捷键设置中核实独立命令；没有时再另行评估公开辅助功能界面中的任务列表导航，单独验收，不读取私有数据库或协议，不以固定 Tab 次数猜焦点。

## 用户最终批准的完整 12 键矩阵

“—”表示该手势不另配置；保留空格是为了避免迟延或误触，并非遗漏功能。以下是最终批准方案；除返回配置的单独回验外，不表示最新完整方案已安装或实体通过。

| 实体键 | 单击 | 双击 | 长按 | 操作理由 |
| --- | --- | --- | --- | --- |
| 主页 Home | 打开/切到 Codex，`open_app: codex` | 新建聊天，`Ctrl+N` | 设置，`Ctrl+,` | 聚合应用入口、新任务和设置 |
| 菜单 Menu | 命令菜单，`Ctrl+Shift+P` | 选择模型，`Ctrl+Shift+M` | 下一个待处理聊天，`Ctrl+Alt+A` | 用一个键管理命令、模型与待办 |
| TV | 查看改动，`Ctrl+Alt+B` | 开关侧边栏，`Ctrl+B` | 撤销，`Ctrl+Z` | 用户不使用终端；把撤销移至明确长按，避免快速退格误触 |
| 电源 Power | `Esc` | — | — | 保留立即退出菜单/取消；审批框内会拒绝请求，不做锁屏或退出应用 |
| 上 | `Up` | — | 按住重复上移 | 保留光标和列表导航；空输入框中可能调出上一条输入 |
| 下 | `Down` | — | 按住重复下移 | 同上，保持方向一致 |
| 左 | `Left` | — | 按住重复左移 | 精细修订听写文本 |
| 右 | `Right` | — | 按住重复右移 | 精细修订听写文本 |
| 确定 OK | `Enter` | — | — | 一次确认；不增加双击发送、连发发送或长按审批 |
| 返回 Back | 立即普通退格，`normal_backspace` | —，快速连按继续删除 | 按住普通连删；长按配置格留空 | 实测快速删除会误触双击撤销，因此不默认绑定撤销 |

| 音量 − | 下一个会话或标签页，`Ctrl+PageDown` | — | 按住重复切换 | 下键对应后一项，与音量 + 成对 |

Codex 专用组合键依据见 [官方 Windows 表](https://learn.chatgpt.com/docs/reference/commands)；方向键、普通退格、应用启动以及按住重复是 SayAll 既有行为。该表含 12 个单击职责、3 个双击职责和 3 个独立长按职责，未将所有配置格填满。撤销仍作为普通快捷键动作，可在任意可编辑的单击、双击或长按格自行配置，也可禁用。

语音键独立于这 12 键：继续按下开始、松开结束。若用户选用 Codex 听写，使用语音设置中的 `Ctrl+Shift+D` 成对生命周期，不由普通手势识别器处理；不加双击等待、不加长按阈值、不在结束录音时自动 Enter。官方默认表列出了听写组合键，但功能是否可用仍取决于应用状态。[官方命令表](https://learn.chatgpt.com/docs/reference/commands)

## 手势的真实代价

下列结论来自本仓库当前源码，不是 Codex 官方响应时延承诺：

- 普通单击键没有双击/长按配置时，在 DOWN 触发。方向与音量按住约 350ms 后开始重复，随后约每 100ms 一次；OK、Home、Menu、TV、Power 本身不自动连发。
- 配置普通双击后，第一击松开要等待约 300ms；第二击在窗口内按下、随后松开触发双击。Home、Menu、TV 因而有此等待，适合不需连续点按的工具动作。
- 只配长按、不配双击也有成本：短按动作移至 UP，长按约 550ms 触发。因此不建议顺手给方向、音量、Esc 都加长按功能。
- 用户先试用 Back 双击 `Ctrl+Z`，随后在 2026-09-21 实测中发现快速删除会触发撤销，明确取消这项默认绑定。最终 Back 单击立即普通退格、快速连按各自退格、按住按 Windows 重复参数连删；Double/Long 配置格留空，不等待手势分类或读取 UIA。用户确认最终配置“正常了”，具体证据见 [普通返回实体回验](../../Testing/evidence/plain-back-physical-20260921.json)。
- 音量纯单击虽然最快，按住也可能连续跳过多个会话。先保留一致的现有行为并实测；若用户偏好“一按只切一个”，这是重复策略的产品选择，不能以塞入一个无关长按动作暗中改变。

## 防止误操作与实现范围

所有普通快捷键发送给当前前台应用，并没有自动识别 Codex 的配置层。先 Home 切到 Codex，再使用专用动作；Home 双击/长按发出的也是普通组合键，不会先自动执行其单击的应用启动。不要声称该配置能从任意前台窗口安全新建 Codex 任务。

OK 保留普通 Enter：它在输入框中可能发送，在审批框中可能批准，在终端中可能执行命令。物理位置虽自然，仍不能命名为“安全确认”。建议不配置任何额外发送/审批手势，不把语音松开、长按音量、任务切换与 Enter 串联。也不默认绑定归档、关闭窗口、退出应用、环境主操作或全选删除。

最终默认撤销由 TV 长按发送 `Ctrl+Z`，不会先执行 TV 的单击动作。撤销仍可自由配置到任意可编辑格或关闭。如果用户自行将 Back 双击配置为 `Ctrl+Z`，首击会先普通退格，双击再发送撤销，快速连续删除也会被如此分类。本轮用户因这一冲突取消返回的默认撤销绑定；旧实体结果见 [原 Undo 方案回验](../../Testing/evidence/daily-undo-physical-20260921.json)。撤销的编辑分组由当前应用决定，不能承诺撤回整段听写或只恢复一个字符。[官方命令表](https://learn.chatgpt.com/docs/reference/commands)

若改成“短按换行、长按发送”，既会改变确认键的即时行为，也要处理已有键盘来源冷首按可能原生泄漏的边界，不能仅改预设便承诺避免误发送。本轮保留 Enter 的原生语义。

最小实施范围为日常方案构造、方案说明及其预设测试，以及确保 Back 的普通首击不被双击配置延迟；继续复用既有备份/恢复机制，不自动覆盖用户已存配置，不改驱动、监听、语音或手势阈值。音量严格聊天能力若以后需要，应独立处理，不能将本次快捷键配置表述成已经实现该能力。
