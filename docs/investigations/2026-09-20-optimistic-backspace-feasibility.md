# 首击提前退格、双击保留标点删除：可行性调查

日期：2026-09-20。初始范围为只读核对现有实现和 Microsoft 公开文档、对自家固定 WebView 测试输入框执行只读预检；随后新增候选产品 Runtime 的受控真实 UIA/输入验证，分节记录。只使用固定测试文本，不采集用户编辑内容。

## 结论与当前状态

用户期望返回键单击及时执行普通 Backspace；若随后形成双击，则补偿首击，执行“删到最近标点，保留标点”。这个方向可在满足条件的文本控件中研究实现，不能据此承诺通用应用零延迟或无条件安全还原。

**该轮已安装版本仍在首击释放后等待 300ms；源码中的提前退格候选已有受控真实执行，尚未安装交付。** 初始只读实验取得一次探针进程首轮及十次热态耗时，并确认目标测试控件支持公开组合态查询。随后真实软件测试验证普通首删、英文/中文标点恢复、单个 emoji 与取消；无标点删空曾因最终校验错误 failed，窄范围空字段确认修复后独立复验 passed，原失败保留。真实闲置首用、活动 IME 组合态和实体遥控器端到端延迟仍未验证，不能宣称零延迟或普遍兼容。

既有双击动作是 `delete_to_punctuation`，不是 Ctrl+Backspace，也不是 Ctrl+Z。最初归档时，本地已启用该动作，`alpha, bravo` → `alpha,` 是**当前实现的验收目标**；此后的现有双击修复与执行验收仍单独记录于 [RC003 集成验收](../../Testing/WindowsRc003Input.md)。本页的只读预检结果不是这项实际删除或新补偿方案通过的证据。

全部样本的 TextEditPattern 均可用，公开 `GetActiveComposition` 返回 **S_OK（0）及 null range**，可确认这些采样时刻没有活动组合态。探针通过公开 COM 方法的 HRESULT 和输出指针分别记录这一事实，没有把“不支持接口”视作“无组合态”。尚未执行正在拼音组字时的正对照。

这里的首轮只表示**新探针进程第一次读取**，目标应用已经运行，不是应用冷启动或等待真实闲置后的首击。表内整体耗时包含用于隔离测试范围的 fixture 查找；即使未来产品可从当前焦点直接开始，也不能简单扣除这项成本，把剩余时间当作已测得的产品延迟。所有轮次都需要文档边界 clamp，这也说明不能省略相应范围验证。

## 调研开始时的已有实现与来源

- [text_edit.rs](../../crates/sayall-windows/src/text_edit.rs)：读取有上限的光标前文本，定位并保留最近标点或段落边界；拒绝已有选区、受保护/只读内容和不支持的范围。复核焦点、光标、文本后，通过 UIA 选择确切范围，再发送一次 Backspace。没有文本插入接口。
- [button_gestures.rs](../../crates/sayall-windows/src/button_gestures.rs)：配置双击时，首击释放后等待 300ms；窗口内第二击释放触发双击。已有测试明确要求双击之前不先删掉字符或标点，并覆盖按住重复、迟到事件和取消。
- [button_mapping.rs](../../crates/sayall-windows/src/button_mapping.rs)：普通退格直接提交键盘动作；标点删除在独立工作线程执行，具有忙碌和取消 generation。提前退格不能直接套成两次互不关联的动作。
- [send_input_windows.rs](../../crates/sayall-windows/src/send_input_windows.rs)：已有成对键盘注入，但本次核查未见 `KEYEVENTF_UNICODE` 文本恢复路径。
- [ATTRIBUTION.md](../../ATTRIBUTION.md) 的既有手势来源采用按配置启用双击、保留判定窗口的语义；没有记录已验证的“首删后补回”实现。本调查的补偿方案是待验证设计推论，不冒称已有成熟参考。

Microsoft 明确 [TextPattern 不提供文字插入/修改接口](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/ui-automation-textpattern-overview)，大部分操作依赖跨进程调用，文本内容也没有其他模式那样的缓存机制。恢复文字需另用公开输入接口；[KEYBDINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput) 的 `KEYEVENTF_UNICODE` 可以提交 Unicode 输入，但不保证目标应用最终接受，也不恢复原有富文本格式。

## 为什么必须有首删前快照

例如光标位于末尾：

| 原文 | 首击后 | 双击目标 | 推论 |
|---|---|---|---|
| `你好，世界` | `你好，世` | `你好，` | 若确证只发生该次退格，直接删除剩余后缀即可，不必先恢复“界” |
| `你好，` | `你好` | `你好，` | 首击已删掉必须保留的逗号，需要恢复逗号，并停止继续向前删除 |

仅在首击后读取 `你好`，无法区分原本是 `你好，` 还是本来就没有标点。保存一个 UIA range 引用也不等于保存删除前的不可变文本；需要实际读取并保存有限文本及对应焦点、选区和光标条件，只在内存保留，不写入日志。

删除前查询**不需要固定等待 300ms 双击窗口**，但仍必须先等查询完成再发送首删。现有 UIA 每次连接/事务超时为 300ms、操作预算为 2s；这些是上限，不是实测延迟。后台预读缓存可以研究，但不能假定公开 UIA 事件及时性或缓存新鲜度能够提供原子保证。UIA 校验与 SendInput 之间始终存在非原子的时间窗口。

## 最小待验证实现范围

1. 仅针对“单击普通退格 + 双击按标点删除”建立短期编辑事务，由独立 MTA worker 串行处理，不阻塞钩子、BLE 或 UI 线程。
2. 首删前确认同一前台输入框、空选区、可写、非密码及可确认无输入法组合态；读取有限上下文，再次检查焦点与取消状态，然后提交普通退格。
3. 首删后只接受同一位置发生可解释的删除；双击时再次核对上下文和光标。若被删内容属于目标后缀，仅删除剩余后缀；跨过需要保留的边界时，才考虑精确恢复。恢复后必须验证实际结果，不能把 SendInput 返回成功当作文字已恢复。
4. 手势状态记录“首击已执行”，避免窗口到期、迟到第二击或按住转连删时重复执行首击。失焦、取消、断连、配置变化或新文本编辑均作废事务，不在新焦点补字，也不撤销已完成的普通首删。
5. 不使用 Ctrl+Z、剪贴板或整框 ValuePattern.SetValue 恢复；不读取私有配置、进程内存或私有编辑器协议。

## 必须验证或拒绝的边界

| 场景 | 当前设计要求 |
|---|---|
| 已有选区 | 首击可能删除整个选区，不能按一个字符恢复；初版禁用该次补偿，保留普通退格语义 |
| IME 正在组合/转换 | Backspace 可能修改组合串而非已提交文本；不启用补偿 |
| IME 状态接口不可用 | 不能视为“没有组合态”，应拒绝该次补偿 |
| 焦点、光标、选区或文本变化 | 放弃补偿和进一步批量删除，不往新的位置插字 |
| Emoji、代理对、组合字符 | 不假定一次 Backspace 等于一个 Rust `char` 或一个 UTF-16 单元；核对实际删除片段，不确定就拒绝 |
| 段落、富文本、嵌入对象 | 补回纯文本无法保证恢复格式或段落结构；初版不支持这种补偿 |
| UIA provider 不支持、超时或保护输入框 | 保留普通退格，说明增强动作不可用；不得猜测被删字符或回退为更大范围删除 |
| 首击无实际删除、部分输入提交、恢复未生效 | 不假设成功；依据观察停止，记录固定原因而不记录文本 |

IME 可查询公开 [IUIAutomationTextEditPattern::GetActiveComposition](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationtexteditpattern-getactivecomposition)，但必须先确认目标 provider 支持；接口缺失与返回“无组合”不是同一种结果。[UIA TextUnit_Character](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-uiautomationtextunits) 是语言相关的文本单位，不能把其数量直接当成 UTF-16 单元数或应用 Backspace 的删除数量。

下一步候选是最小事务实现，而不是增加持续文本缓存：首个 DOWN 将“首删前快照 + 一次普通 Backspace”提交给同一工作线程；300ms 只保留作第二击分类，不再作为单击执行等待。快照不支持或超过预检截止时，普通退格只能执行一次，迟到快照必须作废。截止值与真正首击延迟需用候选实现测量，不能从上述 fixture 定位成本直接推算。新事务的取消 token 要独立于现有批量删除 token，避免首击 UP、第二击 DOWN 取消自己的快照；开始连删、其他操作、焦点变化与生命周期重置则清除待补偿事务。

实现验收需覆盖首轮/热态/真实闲置首击、单击窗口到期不重复删除、双击普通后缀、末尾标点恢复、选区、活动 IME、Unicode、迟到查询和按住取消。日志记录阶段、结果、耗时与固定拒绝原因，不记录文本、窗口标题或设备身份。上文 `passed` 仅指已执行的只读预检；后续产品真实执行单独记录于文末，不将两个阶段混合为端到端验收。


## 候选实现边界（2026-09-20）

候选 `backspace_transaction.rs` 在独立 MTA 线程从当前焦点取得有限快照，准备完成即提交首删。300ms 只参与第二击分类；200ms 是此次候选预检的兜底截止值，依据上表新探针首轮/热态观测选取，不能视为已测得的产品冷首击时延。准备线程与兜底共用一次发送票据，迟到准备不得再次发送。获准的兜底最多执行一次普通退格，并使该次双击补偿不可用；准备阶段已知输入目标变化或输入活动无法确认时应拒绝，不能承诺所有不支持或超时状态都补发按键。

事务要求可写、非密码、单一空光标，整个文档不超过 2048 UTF-16 单位；组合态与转换目标均须公开 API 明确返回 S_OK 和空范围。文本只保存在当前事务内存，不写入日志。不支持这些条件时保留普通退格，不猜测双击恢复内容。首删后仅接受可解释的单个 Unicode scalar 删除（包括两个 UTF-16 单位的普通 emoji）；多 scalar 的复杂字素删除暂拒绝补偿。

第二击确认同一字段、前台、光标及全文未变后，原标点仍在则删除剩余后缀；原标点刚被首击删去则仅以成对 Unicode 输入补回必要边界，并读取实际结果确认。补回控制符、换行与段落分隔符被拒绝，不承诺富文本格式恢复。取消、其它语义键、连续退格、断连、配置变化和退出均作废事务；选区清理期间不允许其它映射输入穿过。没有通用撤销、剪贴板或整框赋值。

同票据竞争与迟到处理、取消和 busy 门控已有不发送真实键的自动化测试；手势与引擎衔接另有定向测试。这些不等于实际输入通过。早期 Windows 拒绝探针自动取得自家窗口前台，相关执行返回 deferred 且未发送按键；用户随后聚焦后的真实执行见下节，原 deferred 证据不改写为 passed。

## 候选真实软件执行（2026-09-20）

[版本化证据](../../Testing/evidence/optimistic-backspace-webview-20260920.json) 汇总 `15:10:14Z–15:12:39Z` 的 9 项 passed、1 项 failed。探针直接调用产品 `backspace_transaction::Runtime`，使用真实公开 UIA、成对 Backspace/Unicode 输入，并比较最终 ValuePattern 精确预期；不是模拟，也不经过实体遥控器或手势分类。

- passed：普通后缀 12→11→6，首击提交 45ms，动作 545ms；重复两次也通过，首击均 30ms，结束约 504ms、520ms。504ms 来自产品 begin 到 shutdown 日志，其 stdout 被下一轮覆盖。
- passed：单次首删 12→11，提交 28ms；英文标点 6→5→6、中文标点 3→2→3，分别 138ms、130ms 完成并实际观察恢复结果；单 scalar emoji 8→6，98ms 完成。
- passed：首删后取消，12→11 后禁止 complete，48ms；选择生效时取消，187ms 内确认文本 12 不变和原末尾空光标恢复。后一项 `cleanup_wait_caret pending_count=1 observed_ms=16`，直接观察到异步恢复；执行方观察 input 事件为空。
- failed：无标点实际 5→4→0，预期文本匹配，但产品返回 `unsupported_text_content`，总耗时 531ms。只读复核空 `<input>` 的 ValuePattern 为空，DocumentRange 返回一个 U+FFFC，空光标在范围起点。需严格空字段交叉校验后再复验，不能因最终值正确就忽略 API 失败或普遍接受嵌入对象。

`15:16:02Z` 空字段修复独立复验 passed：首击提交 39ms、动作 559ms、实际 5→4→0，API、焦点和精确预期均通过。仅当可写 Edit 的 ValuePattern 为空、DocumentRange 为单个 U+FFFC、唯一空光标在起点，且重复两次组合态/焦点/字段确认均成功时，接受该空字段表示；仍拒绝普通嵌入对象。产品日志为 `empty_result_verify ... writable_empty_value_placeholder_confirmed`，最新事务定向测试 23 passed。累计保留 10 项软件 passed 和 1 项历史 failed，不覆盖原始失败事实。

首击 28–48ms 指输入提交回调耗时，不等于 DOM 响应时延。探针在首删回调后立即请求 complete，且调用前会读取 UIA fixture；数值不能当作双击判定、实体遥控器、未经预热冷态或闲置首用指标。单次首删后立即 shutdown，也未覆盖手势窗口到期不重复删除的真实输入链。活动 IME、已有选区、复杂多 scalar 字素、其它应用、富文本格式、新安装和实体生命周期仍待独立验证。

## 截止兜底审查补充

代码审查发现两处条件不足：准备阶段报告 `focus_changed` 后仍转普通兜底；截止线程只检查同一前台 HWND，无法识别窗口内用户点击或切换另一字段。修复不改变 prepared 的精确 UIA 路径及 200ms 截止值：事务 begin 记录 GetLastInputInfo，只有兜底发送前读取成功且 tick 与起始相等才允许提交一次退格；已知焦点、光标、选择或文本变化直接取消本代事务，不再让其截止线程补发。读取失败或活动改变在同一短锁内消费票据并取消该事务，已排队的双击请求得到拒绝结果；回调在锁外执行。旧准备失败只取消自己的 Transaction，不推进共享 epoch，避免误取消后代。

依据 Microsoft [GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo)，返回零是调用失败；它只覆盖当前会话，tick 可能倒退，SendInput 也可能改变值。此处不计算先后或经过时间，只以“不等/不可读”为拒绝依据。它是输入活动的附加保护，不是 UIA 元素或字段身份证明：同 tick 活动、无输入的程序性换焦以及检查到注入之间的竞态仍不能据此排除。可能因此保守放弃一次兜底，不应宣称无条件保留每次普通退格。

新增 4 项 fake-send 定向测试 passed，事务模块累计 27 passed、0 failed：覆盖 tick 未知/改变/倒退/回绕、prepared 不读取 tick、已知上下文变化阻止截止发送且不取消后代、活动失效后双击只报告一次并释放 busy。源码窄审查确认取消只作用于当前事务、票据和活动校验在同一短锁内、回调在锁外。既有 10 项软件成功结果均不证明此兜底路径经过实体遥控器、同窗口换字段或未经预热闲置验证；不把模拟测试、API 可调用或源码检查写成该路径真实输入 passed。
